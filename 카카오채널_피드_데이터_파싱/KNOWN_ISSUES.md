# 카카오채널 피드 파싱 알려진 문제

이 문서는 환경별 장애와 해결 이력을 보관한다. 정상 실행에서는 `카카오채널_피드_데이터_파싱.md`만 따르고, 관련 오류가 발생했을 때 이 문서를 참고한다.

## Windows PowerShell 이미지 다운로드 TLS 오류

- 발생일: 2026-08-11
- 대상: `k.kakaocdn.net` 대표 이미지
- 실패 방식: Windows PowerShell `Invoke-WebRequest`
- 예외 유형: `System.Net.WebException`
- 오류 메시지: `기본 연결이 닫혔습니다. 받기에서 예기치 않은 오류가 발생했습니다.`
- 내부 오류: `보안 패키지에 사용할 수 있는 인증서가 없습니다.`
- 대체 처리: 동일 URL을 Node.js 또는 브라우저 런타임의 `fetch`로 다운로드하면 정상 처리됨
- 판정: 이미지 URL이나 파일 문제가 아닌 실행 환경의 인증서/TLS 호환 문제

### 대응

1. 대표 이미지의 기본 다운로드 방식으로 Node.js `fetch`를 사용한다.
2. 실패하면 브라우저 컨텍스트의 `fetch`로 재시도한다.
3. 모든 방식이 실패한 경우에만 CSV를 `warning`으로 기록한다.
4. 체크포인트 또는 실행 로그에 방식별 예외 유형, 원본 메시지와 재시도 결과를 남긴다.

## Windows PowerShell JSON 배열 중첩

- 발생일: 2026-08-11
- 발생 단계: 체크포인트 JSON의 11~20번 결과를 기존 CSV와 병합
- 증상: `ConvertFrom-Json` 결과를 다시 `@(...)`로 감싸 배열이 한 번 더 중첩되면서 10개 상품이 한 행처럼 처리됨
- 오류: `null 배열에 대한 인덱스를 만들 수 없습니다.` 및 여러 `sort_order` 값의 정수 변환 실패
- 영향: 중간 CSV 병합 실패. 상품별 HTML·TXT·썸네일과 원본 체크포인트에는 영향 없음
- 복구: 기존 정상 1~10번과 체크포인트 11~20번을 다시 병합하여 최종 20행 검증 완료

### 대응

1. PowerShell 5.1에서 JSON 최상위 배열을 읽을 때 `ConvertFrom-Json` 결과를 불필요하게 `@(...)`로 다시 감싸지 않는다.
2. CSV 확정 전에 예상 행 수, `sort_order`의 단일 숫자 여부와 순번 범위를 검사한다.
3. 병합 실패 시 중간 CSV를 신뢰하지 말고 기존 정상 범위와 체크포인트에서 재생성한다.
