# 카카오채널 피드 데이터 파싱

이 문서는 카카오톡 채널 게시물 URL 목록을 상품 업로드용 데이터로 변환하기 위한 재사용 작업 명세다. 작업을 시작할 때 이 문서와 입력 CSV를 Codex에 제공한다.

## 1. 입력값

필수 입력:

- `input_csv`: 카카오 게시물 목록 CSV 경로
- 필수 입력 열: `order`, `post_id`, `post_url`
- `output_dir`: 결과 폴더 경로

기본값:

```text
input_csv  = kakao-channel-products/manifest.csv
output_dir = kakao-channel-products/admin-output
```

선택 입력:

- `start_order`: 시작 순번. 기본값은 첫 행
- `limit`: 처리 개수. 기본값은 전체
- `overwrite`: 기존 결과 덮어쓰기 여부. 기본값은 `false`
- `max_retries`: URL별 재시도 횟수. 기본값은 `2`

## 2. 실행 전 확인

1. 입력 CSV가 존재하고 필수 열을 포함하는지 확인한다.
2. 전체 실행 전 첫 행 하나를 샘플 처리해 사용자의 검수를 받는다.
3. 기존 결과가 있으면 임의로 삭제하거나 덮어쓰지 않는다.
4. 페이지 구조가 이 문서와 다르면 전체 실행을 중단하고 차이를 보고한다.

## 3. 페이지 로딩

각 `post_url`에 접속한 뒤 다음 조건을 모두 만족할 때 파싱한다.

1. 문서의 `readyState`가 `complete`일 것
2. 가능한 경우 네트워크 유휴 상태까지 기다릴 것
3. `div.wrap_archive_content`가 DOM에 생성될 때까지 기다릴 것
4. `div.wrap_archive_txt`, `.tit_card`, `.desc_card`의 존재를 확인할 것

초기 HTML 응답만 파싱하지 않는다. 이 페이지는 동적 로딩 완료 전 하위 DOM이 없을 수 있다.

## 4. 상품 데이터 파싱

기준 선택자:

- 상품명: `.tit_card`
- 설명: `.desc_card`
- 본문 텍스트: `div.wrap_archive_txt`
- 본문 HTML 및 이미지: `div.wrap_archive_content`

추출 규칙:

- `product_name`: `.tit_card`의 정리된 텍스트
- `product_code`: `.desc_card` 상단에서 품번처럼 보이는 영문·숫자 조합
- `product_colors`: `색상`, `컬러`, `color` 라벨의 값
- `retail_price`: `소비자가`, `소비자`, `판매가` 라벨의 값에서 숫자만 남긴 정수
- `image_count`: `.wrap_archive_content` 아래의 실제 `img` 요소 개수
- `color_count`: 색상 값을 `/`, `,`, `·`, 줄바꿈 등 실제 구분자에 따라 나눈 고유 색상 수

가격이 `문의`, 빈 값 또는 파싱 불가능한 값이면 `retail_price`를 비우고 `parse_status=warning`으로 기록한다.

## 5. 속성 파싱

본문에서 `속성명 : 값` 또는 `속성명：값` 형태를 줄 단위로 찾는다. 공백과 콜론 모양의 변형을 허용한다.

고정 속성 열:

| 원문 라벨 | CSV 열 |
|---|---|
| 색상, 컬러 | `attr_color` |
| 품질 | `attr_quality` |
| 생산, 제조 | `attr_production` |
| 소비자가, 소비자, 판매가 | `attr_retail_price` |
| 둘레, 사이즈 | `attr_circumference` |

`소재`, `재질`을 포함하여 위 고정 목록에 없는 라벨이나, 오입력·오기·비정상 표기로 의심되지만 상품 정보일 가능성이 있어 버리기 애매한 값은 삭제하지 않는다. 실제로 발견된 경우에만 발견 순서대로 다음 동적 열에 원문 라벨과 값을 그대로 저장한다.

```text
extra_attr_1_name, extra_attr_1_value
extra_attr_2_name, extra_attr_2_value
...
```

동적 열 운용 규칙:

1. `extra_attr_N_name`, `extra_attr_N_value`는 기본 CSV에 미리 만들지 않는다.
2. 처리한 전체 상품에서 보존할 추가 속성이 한 건이라도 발견된 경우에만 필요한 개수만큼 추가한다.
3. 라벨의 의미를 확실히 판단할 수 없거나 오입력이 의심되면 임의로 고정 속성에 매핑하거나 내용을 교정하지 않고 원문 그대로 보존한다.
4. 같은 의미가 명확한 정상 표기만 고정 속성에 매핑한다. 판단이 애매하면 동적 열에 넣고 `parse_status=warning` 및 `error_text`에 검수 사유를 기록한다.
5. 어떤 상품에도 추가 속성이 없으면 최종 CSV에 `extra_attr_N_*` 열은 존재하지 않는다.

연락처, 카카오톡 ID, 매장번호, 주소 등 상품과 무관한 정보는 속성으로 수집하지 않는다.

## 6. 텍스트 수집 범위

`div.wrap_archive_txt`의 시작부터 `둘레 : 56cm~58cm(사이즈 조절 가능)`에 해당하는 줄까지 수집한다. 아래와 같은 표기 변형도 종료 기준으로 인정하며 해당 줄은 결과에 포함한다.

```text
둘레 : 56cm~58cm(사이즈 조절 가능)
둘레: 56~58cm (사이즈 조절 가능)
사이즈 : 56-58cm
```

종료 기준을 찾지 못하면 상품 설명 전체를 저장하고 `parse_status=warning` 및 `error_text`에 사유를 기록한다.

## 7. 결과 폴더와 파일명

루트 구조:

```text
admin-output/
├─ product_upload.csv
└─ 품번_한글상품명/
   ├─ 품번.html
   ├─ 품번.txt
   └─ 품번_thumb.확장자
```

예시:

```text
admin-output/
├─ product_upload.csv
└─ 6B524_어드밴쳐 긴챙 등산모/
   ├─ 6B524.html
   ├─ 6B524.txt
   └─ 6B524_thumb.png
```

파일명 규칙:

1. 폴더명은 `product_code_product_name`으로 만든다.
2. Windows에서 사용할 수 없는 문자 `\ / : * ? " < > |`는 `_`로 바꾼다.
3. HTML, TXT, 썸네일 파일명은 한글 상품명 대신 품번을 사용한다.
4. 품번과 상품명이 모두 같은 폴더가 이미 존재하면 `품번_상품명_post_id`로 저장한다.
5. 품번을 찾지 못하면 `NO_CODE_post_id_상품명` 폴더를 사용하고 파일명에는 `post_id`를 사용한다.
6. `overwrite=false`일 때 기존 파일을 덮어쓰지 않는다.

## 8. HTML 저장

`div.wrap_archive_content`의 `outerHTML`을 가져와 다음 기본 문서 구조에 넣는다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>상품명</title>
</head>
<body>
  <!-- wrap_archive_content의 outerHTML -->
</body>
</html>
```

원본 이미지 URL은 그대로 유지한다. HTML 파일은 브라우저에서 단독으로 열 수 있어야 한다.

## 9. 썸네일 저장

1. `.wrap_archive_content` 아래 첫 번째 `img`의 실제 원본 이미지만 저장한다.
2. 확장자는 URL 문자열보다 응답의 콘텐츠 유형을 우선하여 결정한다.
3. 저장명은 `품번_thumb.확장자`로 한다.
4. 이미지 다운로드 실패 시 나머지 데이터와 파일은 보존하고 `parse_status=warning`으로 기록한다.

## 10. CSV 스키마

기본 열 순서:

```text
sort_order
post_id
post_url
product_name
product_code
product_colors
retail_price
image_count
color_count
attr_color
attr_quality
attr_production
attr_retail_price
attr_circumference
html_file_path
text_file_path
thumbnail_file_path
parse_status
error_text
```

위 목록은 고정 기본 스키마다. `extra_attr_N_name`, `extra_attr_N_value`는 고정 기본 열이 아니다. 알려지지 않은 속성이나 오입력 의심 속성을 실제로 보존한 상품이 있을 때만 필요한 만큼 `attr_circumference` 뒤, `html_file_path` 앞에 추가한다. 모든 행을 먼저 수집한 뒤 행별 추가 속성 개수의 최댓값을 계산하여 최종 CSV 헤더를 한 번에 확정한다. 추가 속성이 전혀 없으면 동적 열을 추가하지 않는다.

경로는 `output_dir` 기준 상대 경로로 저장하고 `/` 구분자를 사용한다.

## 11. 상태값

`parse_status`는 다음 값만 사용한다.

- `success`: 필수 값과 파일을 모두 정상 생성
- `warning`: 결과는 생성했지만 일부 값 누락 또는 검수 필요
- `failed`: 게시물을 파싱하지 못해 정상 결과 생성 불가

`error_text`에는 사람이 이해할 수 있는 짧은 한국어 설명을 기록한다. 여러 오류는 ` | `로 구분한다.

경고 예시:

- 품번을 찾지 못함
- 가격을 정수로 변환하지 못함
- 텍스트 종료 기준을 찾지 못함
- 대표 이미지 다운로드 실패
- 본문 색상과 대표 이미지 색상이 달라 검수 필요
- 중복 폴더명으로 `_post_id`를 추가함

## 12. CSV 인코딩 및 검증

1. `product_upload.csv`는 UTF-8 BOM 형식으로 저장한다. Windows Excel에서 한글이 깨지는 것을 줄이기 위한 설정이다.
2. 첫 3바이트가 `EF BB BF`인지 확인한다.
3. CSV를 다시 읽어 모든 행의 열 개수가 헤더와 같은지 확인한다.
4. `retail_price`, `image_count`, `color_count`는 숫자 문자열만 허용한다.
5. 각 행의 HTML, TXT, 썸네일 상대 경로가 실제 파일과 연결되는지 확인한다.
6. 성공·경고·실패 건수를 최종 보고한다.

## 13. 전체 실행 안정성

1. URL 하나가 실패해도 전체 실행을 중단하지 않는다.
2. URL별로 최대 `max_retries`만큼 재시도한다.
3. 처리 결과를 주기적으로 체크포인트에 기록한다.
4. 재실행 시 이미 완료된 `post_id`를 식별하여 불필요한 재수집을 피한다.
5. 사이트에 과도한 요청을 보내지 않도록 순차 처리하거나 적절한 동시성 제한을 둔다.
6. CAPTCHA, 로그인 또는 접근 제한이 나타나면 우회하지 말고 사용자에게 보고한다.

## 14. 실행 요청 예시

다른 Codex 작업에서 다음처럼 요청한다.

```text
첨부한 `카카오채널_피드_데이터_파싱.md` 명세대로 작업해줘.

input_csv: C:/작업폴더/manifest.csv
output_dir: C:/작업폴더/admin-output
start_order: 1
limit: 전체
overwrite: false

먼저 첫 행 하나만 처리해 결과를 보여주고, 내가 승인하면 나머지 전체를 처리해줘.
```

- 실패 수
- 생성된 `product_upload.csv` 경로
- 실패 또는 검수 필요 항목 요약
- 실제 결과 파일 경로 검증 여부
