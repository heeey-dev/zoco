# 카카오채널 상품 게시물 수집 프로젝트 — Codex 인수인계서

## 0. Codex 시작 지시

이 문서를 처음부터 끝까지 읽은 뒤 작업한다.

- 사용자가 아래 입력값을 전달하기 전에는 웹사이트 접속이나 파일 수집을 시작하지 않는다.
- 전체 작업을 한 번에 진행하지 않는다.
- 각 승인 체크포인트에서 현재 결과를 사용자에게 보여주고 명시적인 승인을 받은 후 다음 단계로 이동한다.
- 목록 수집과 상세페이지 처리를 섞지 않는다.
- 기존 결과물을 자동으로 덮어쓰거나 삭제하지 않는다.
- 페이지 구조가 예상과 다르면 추측하여 강행하지 말고 샘플 결과와 차이를 보고한다.

---

## 1. 사용자 입력값

사용자가 Codex 대화에서 다음 3개 입력 그룹을 다시 전달한다. 사용자는 **한글 입력 양식과 영문 YAML 양식 중 편한 형식 하나만 사용**하면 된다. Codex는 한글 필드명을 아래 영문 키로 내부 변환한다.

### 1.1 한글 입력 양식

사용자에게는 이 양식을 우선 안내한다.

```text
1. 카카오채널
- 채널 메인 주소:
- 상품 목록 주소:

2. 마지막 게시물
- 마지막 게시물 주소:
- 마지막 게시물 고유번호:
- 목록에 노출된 href: (알고 있을 때만 입력)

3. 마지막 게시물 상품 정보
- 상품명:
- 상품 품번:
```

`목록에 노출된 href`만 선택 입력값이며 나머지는 필수다.

### 1.2 영문 YAML 입력 양식

```yaml
channel_main_url: ""
channel_posts_url: ""
end_post:
  url: ""
  post_id: ""
  product_name: ""
  product_code: ""
  list_href_if_known: ""
```

### 1.3 한글·영문 필드 대응표

| 한글 필드 | 영문 내부 키 | 필수 여부 |
|---|---|---|
| 채널 메인 주소 | `channel_main_url` | 필수 |
| 상품 목록 주소 | `channel_posts_url` | 필수 |
| 마지막 게시물 주소 | `end_post.url` | 필수 |
| 마지막 게시물 고유번호 | `end_post.post_id` | 필수 |
| 상품명 | `end_post.product_name` | 필수 |
| 상품 품번 | `end_post.product_code` | 필수 |
| 목록에 노출된 href | `end_post.list_href_if_known` | 선택 |

### 1.4 한글 입력값 완성 예시

```text
1. 카카오채널
- 채널 메인 주소: https://pf.kakao.com/_XIexbj
- 상품 목록 주소: https://pf.kakao.com/_XIexbj/posts

2. 마지막 게시물
- 마지막 게시물 주소: https://pf.kakao.com/_XIexbj/112603732
- 마지막 게시물 고유번호: 112603732
- 목록에 노출된 href: /_XIexbj/112603732

3. 마지막 게시물 상품 정보
- 상품명: 접이지사 벙거지
- 상품 품번: 6B501
```

### 1.5 동일 예시의 영문 YAML 변환 결과

```yaml
channel_main_url: "https://pf.kakao.com/_XIexbj"
channel_posts_url: "https://pf.kakao.com/_XIexbj/posts"
end_post:
  url: "https://pf.kakao.com/_XIexbj/112603732"
  post_id: "112603732"
  product_name: "접이지사 벙거지"
  product_code: "6B501"
  list_href_if_known: "/_XIexbj/112603732"
```

### 1.6 입력값 검증 및 `false` 처리

Codex는 웹사이트 접속 전에 입력값만으로 다음을 검증한다.

- 채널 메인 주소와 상품 목록 주소의 채널 식별자가 같은가
- 상품 목록 주소가 해당 채널의 `/posts` 경로인가
- 마지막 게시물 주소의 채널 식별자가 같은가
- 마지막 게시물 주소 끝 번호와 입력한 고유번호가 같은가
- `list_href_if_known`가 있으면 그 끝 번호도 고유번호와 같은가
- 상품명과 상품 품번이 비어 있지 않은가
- 상품 품번이 전화번호·가격·치수처럼 명백히 잘못된 값이 아닌가

검증에 실패하면 전체 입력을 막연하게 `false`로만 응답하지 않는다. **문제가 있는 필드만 `false`로 표시하고 이유와 수정 예시를 함께 제공**한다.

예시:

```text
입력값 검증 실패

- 채널 메인 주소: true
- 상품 목록 주소: true
- 마지막 게시물 주소: false
  이유: URL 끝의 게시물 번호와 입력한 고유번호가 다릅니다.
  입력 URL 번호: 112603731
  입력 고유번호: 112603732
- 상품명: true
- 상품 품번: true

수정된 마지막 게시물 주소를 다시 입력해주세요.
웹사이트 접속과 파일 생성은 시작하지 않았습니다.
```

모든 필수값 검증을 통과한 경우에만 다음처럼 응답한다.

```text
입력값 검증: true
```

수집 범위는 `channel_posts_url`에 노출되는 가장 최근 게시물부터 `end_post.post_id`에 해당하는 게시물까지이며, 마지막 게시물도 결과에 포함한다.

## 2. 프로젝트 목적

카카오채널 상품 게시물의 URL 전체를 최신순으로 먼저 확정한 다음, 게시물별 렌더링 HTML을 저장한다. 저장된 원본에서 상품명·품번·본문 텍스트·이미지 정보를 파싱하고, 상품별 폴더에 본문 TXT와 원본 이미지를 저장한다.

최종 상품 폴더명 규칙:

```text
한글상품명_품번고유값
```

예시:

```text
어드벤처 긴챙 등산모_6B524/
├─ content.txt
├─ 001.jpg
├─ 002.jpg
└─ 003.jpg
```

로컬 HTML 재구성은 작업 범위에 포함하지 않는다.

---

## 3. 절대 작업 원칙

1. 메인 목록에서 대상 게시물 URL 전체를 먼저 수집한다.
2. 수집된 URL 목록을 검증하고 사용자 승인으로 확정한다.
3. 확정된 URL만 기준으로 상세페이지 HTML을 저장한다.
4. 웹사이트에 다시 의존하지 않고 저장된 원본을 오프라인 파싱한다.
5. 파싱 결과를 기준으로 본문 TXT와 이미지를 저장한다.
6. 모든 상태는 Manifest와 내부 작업 원장에 즉시 기록한다.

금지되는 방식:

- 게시물 번호를 1씩 증가·감소시키며 URL 추측
- `목록 1개 발견 → 상세 진입 → 목록 복귀` 반복
- 전체 작업이 끝난 뒤 한꺼번에 상태 저장
- 파싱이 불확실한 상품명이나 품번을 임의 확정
- 동일 폴더 또는 파일 자동 덮어쓰기

## 4. 전체 단계

### Phase 0 — 작업 환경 및 샘플 구조 확인

1. 사용자 입력값을 검증한다.
2. 프로젝트 루트 폴더를 만든다.
3. 목록 페이지의 AJAX/fetch 또는 무한 스크롤 구조를 읽기 전용으로 확인한다.
4. 최근 게시물 소량만 수집해 링크 구조, 순서, 중복, 로딩 방식을 확인한다.
5. 상세 게시물 1~3개로 HTML·본문·원본 이미지 URL 보존 가능 여부를 확인한다.

#### 승인 체크포인트 1

사용자에게 다음을 보여주고 승인을 요청한다.

- 최근 게시물 샘플 URL과 `post_id`
- 목록이 최신순인지 여부
- 무한 스크롤 또는 API 로딩 방식
- 종료 게시물 인식 계획
- 예상되는 위험이나 구조 변경 사항

승인 전에는 전체 목록 수집을 시작하지 않는다.

### Phase 1 — 전체 URL 목록 수집

1. 목록 페이지에서 최신순으로 게시물 링크를 수집한다.
2. 새 링크 발견 즉시 내부 원장에 기록한다.
3. `post_id`를 고유키로 중복 제거한다.
4. 고정 게시물은 별도 표시하고 화면 노출 순서를 보존한다.
5. 지정한 마지막 `post_id`를 발견하면 해당 글까지 포함하고 수집을 멈춘다.
6. 마지막 게시물의 URL·상품명·품번을 사용자 입력값과 대조한다.

#### 브레이크 조건

정상 종료:

- 목록의 `href` 또는 상세 URL에서 지정한 `end_post.post_id` 발견
- 해당 URL을 수집 목록에 포함
- 가능하면 마지막 상세페이지의 상품명·품번까지 대조 완료

비정상 또는 안전 종료:

- 실제 목록 끝까지 갔지만 목표 번호가 없음: `end_post_not_found`
- 목표 번호는 같지만 상품 정보가 다름: `end_post_mismatch`
- 연속된 로딩에서 신규 게시물이 나오지 않음: 제한 재시도 후 `collection_stalled`
- 접근 제한·세션 오류: `collection_paused`
- 사용자가 지정한 안전 한도 도달: `safety_limit_reached`

#### 승인 체크포인트 2

전체 상세 처리 전에 다음을 사용자에게 보여준다.

- 전체 수집 URL 수
- 첫 게시물과 마지막 게시물
- 마지막 게시물 검증 결과
- 중복·고정·누락 의심 건수
- 확정 예정 URL 목록 파일

사용자 승인 후 목록을 확정하고 Phase 2로 이동한다.

### Phase 2 — 상세페이지 원본 저장

1. 확정 URL 목록만 읽는다.
2. 게시물을 하나씩 열고 본문과 이미지 지연 로딩 완료를 기다린다.
3. 렌더링된 DOM HTML을 게시물별로 저장한다.
4. 이미지 URL이 HTML에 보존되지 않을 가능성에 대비해 이미지 URL·순서·속성을 `images.json`에도 저장한다.
5. 필요한 경우 공개 네트워크 응답의 게시물 데이터 JSON도 원본으로 저장한다.
6. 게시물 단위 저장 직후 상태를 갱신한다.

#### 승인 체크포인트 3

전체 상세 HTML 저장 전에 1~3개 샘플 결과를 보여준다.

- 저장 HTML 경로와 크기
- 본문 전체가 HTML에 남는지
- 원본 또는 최대 해상도 이미지 URL이 남는지
- 이미지 URL이 시간 경과 후에도 접근 가능한지
- 세션·쿠키·Referer 필요 여부

승인 후 전체 HTML 저장을 진행한다.

### Phase 3 — 오프라인 파싱

저장된 HTML/JSON만 이용해 다음을 추출한다.

- `post_id`
- 원본 게시물 URL
- 상품명
- 품번
- 본문 전체 텍스트
- 이미지 URL 및 표시 순서

상품명 규칙:

- 상품 본문 영역의 첫 번째 유효한 상품명 줄을 우선한다.
- 괄호 속 반복 상품명은 폴더명 생성에서 제외한다.
- 맞춤법과 표현을 임의 수정하지 않는다.
- 앞뒤 공백과 연속 공백만 정리한다.

품번 규칙:

- 상품명 다음에 나오는 독립된 영문·숫자 조합 줄을 우선한다.
- 길이를 고정하지 않는다.
- 전화번호, 가격, 치수 숫자를 품번으로 오인하지 않는다.
- 품번 후보가 없거나 여러 개면 자동 확정하지 않는다.

본문 TXT 규칙:

- UTF-8
- 본문 컨테이너의 텍스트만 추출
- `<br>`과 문단 줄바꿈 보존
- 카카오 UI, 버튼, 메뉴 텍스트 제외
- 원문 내용은 교정·요약하지 않음
- 전화번호와 주소 등 원문 포함 정보는 그대로 보존

#### 승인 체크포인트 4

서로 다른 유형의 샘플 게시물 3~5개에 대해 다음을 보여준다.

- 상품명
- 품번
- 생성 예정 폴더명
- `content.txt` 미리보기
- 이미지 발견 수와 순서
- `review_required` 판단 결과

승인 후 전체 오프라인 파싱을 진행한다.

### Phase 4 — 이미지 다운로드

1. 상품 폴더를 생성한다.
2. 본문 이미지만 원본 노출 순서대로 다운로드한다.
3. `001`, `002`, `003` 순으로 이름을 부여한다.
4. 응답 `Content-Type` 또는 파일 헤더로 실제 확장자를 결정한다.
5. 이미지가 정상적으로 열리는지, HTML 오류 응답이 아닌지 확인한다.
6. 파일 해시로 동일 게시물 내 중복 이미지를 식별한다.
7. 프로필, 아이콘, 채널 배너 등 UI 이미지는 제외한다.

원본 후보 확인 속성:

- `src`
- `srcset`
- `data-src`
- `data-original`
- CSS 배경 이미지
- 저장한 데이터 JSON의 이미지 URL

#### 승인 체크포인트 5

전체 이미지 다운로드 전에 상품 1~3개의 샘플 결과를 보여준다.

- 실제 생성 폴더
- TXT 파일
- 다운로드 이미지 수
- 이미지 해상도·형식
- 썸네일이 아닌 최대 품질 이미지인지

승인 후 전체 이미지 다운로드를 진행한다.

### Phase 5 — 전체 검수

다음을 집계한다.

- 발견 게시물 수
- 확정 URL 수
- HTML 저장 완료 수
- 파싱 완료 수
- 상품 폴더 생성 수
- 저장 이미지 수
- `completed`, `partial`, `review_required`, `failed` 수
- 폴더명 충돌 및 중복 게시물 수

#### 승인 체크포인트 6

최종 결과, Manifest, 검토 필요 목록을 사용자에게 보여준다. 사용자의 최종 확인 전에는 검토 대상의 이름 변경·병합·삭제를 수행하지 않는다.

## 5. 무한 스크롤 안정성

목록의 최종 DOM만 저장하지 않는다. 가상화로 이전 항목이 DOM에서 제거될 수 있으므로 새 게시물 링크를 발견하는 즉시 원장에 기록한다.

우선순위:

1. 공개 목록 API 응답 구조 확인 및 합법적·정상적 범위에서 사용
2. 브라우저 네트워크 응답에서 게시물 링크 확보
3. 자동 스크롤 후 새 DOM 링크 즉시 확보

매 배치마다 다음을 체크포인트로 저장한다.

```json
{
  "last_discovered_post_id": "",
  "discovered_count": 0,
  "target_end_post_id": "",
  "end_post_found": false,
  "updated_at": ""
}
```

재실행 시 최신 목록부터 다시 시작해도 기존 `post_id`는 건너뛰고 이어간다. 고정 시간 대기만 사용하지 말고 신규 ID 발견, 게시물 개수 증가, 로딩 표시 종료 또는 네트워크 완료를 함께 판정한다.

## 6. 상태 관리

### 사용자용 관리표

`manifest.csv`는 사람이 엑셀 등에서 전역적으로 검토하는 어드민용 관리표다.

권장 필드:

```text
order
post_id
post_url
list_title
product_name
product_code
folder_name
html_file
text_file
image_count_found
image_count_saved
parse_status
download_status
overall_status
error_message
discovered_at
collected_at
processed_at
```

### 내부 작업 원장

`collection-queue.jsonl`은 프로그램이 안전하게 이어받기 위한 원장이다. 게시물 하나당 한 레코드를 사용하며 `post_id`를 고유키로 취급한다.

상태값:

```text
pending
discovered
html_saved
parsed
completed
partial
review_required
failed
```

재개 규칙:

- `completed`: 건너뜀
- `html_saved`: 오프라인 파싱부터 재개
- `parsed`: 이미지 다운로드부터 재개
- `partial`: 실패 항목만 제한 재시도
- `review_required`: 사용자 검토 전 자동 재처리 금지

## 7. 예외 처리

다음 경우 `review-required`로 분리한다.

- 상품명 없음
- 품번 없음
- 품번 후보가 여러 개
- 게시물 하나에 여러 상품 또는 여러 품번
- 공지·이벤트 등 상품 게시물이 아님
- 본문과 이미지 영역 구분 불가
- 이미지가 한 장도 저장되지 않음
- 같은 상품명·품번의 다른 게시물 발견

동일 폴더명이 이미 존재하면서 게시물 ID가 다르면 덮어쓰지 않고 다음처럼 보존한다.

```text
상품명_품번__게시물ID
```

본문에는 전화번호와 주소가 포함될 수 있으므로 결과물 외부 공유 시 개인정보 포함 여부를 확인한다. 로그에는 본문 전체를 불필요하게 복제하지 않는다.

접속 제한이 감지되면 무한 재시도하거나 우회하지 않는다. 현재 체크포인트를 보존하고 사용자에게 보고한다.

## 9. 구현 및 검증 기준

- 스크립트는 단계별로 독립 실행 가능하게 구성한다.
- dry-run 또는 샘플 제한 옵션을 제공한다.
- 전체 수집 전 5~10개 이하 파일럿을 수행한다.
- 저장 파일은 기본적으로 덮어쓰지 않는다.
- 재실행해도 완료 항목이 중복 생성되지 않아야 한다.
- 실패한 게시물 하나 때문에 전체 작업이 중단되지 않아야 한다.
- 원본 HTML/JSON과 가공 결과를 명확히 분리한다.
- 주요 설정과 사용자 입력값은 `run-config.json`에 기록한다.
- 서비스 이용정책과 콘텐츠 사용 권한 범위 내에서 수행한다.

## 10. Codex 첫 응답 형식

사용자가 3개 입력값을 제공하면 곧바로 전체 작업을 시작하지 말고 다음을 먼저 응답한다.

```text
입력값 확인 완료
- 채널 메인 URL: ...
- 상품 목록 URL: ...
- 종료 게시물: post_id / 상품명 / 품번
- 예정 저장 경로: ...

첫 번째 작업은 최근 게시물 소량의 목록 구조 확인입니다.
상세 HTML 저장이나 이미지 다운로드는 아직 수행하지 않습니다.
샘플 목록 수집을 시작해도 될까요?
```

사용자가 승인하면 Phase 0의 샘플 목록 확인만 수행하고 다시 멈춘다.
